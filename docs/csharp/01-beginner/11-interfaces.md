# Chapter 11 — Interfaces Deep Dive

> **⚡ Core Idea (30 seconds):** An interface defines a **contract** — a set of methods/properties a class must implement. Unlike abstract classes, a class can implement multiple interfaces. C# 8+ added **default interface methods**, allowing interfaces to have implementations — blurring the line between interfaces and abstract classes.

**Domain:** `C#` **Level:** `Beginner` **Tags:** `#interfaces` `#contracts` `#abstraction` `#default-methods`

---

## 1. Core Idea

Think of an interface like a **power outlet standard**. The standard says "must have 3 pins, 220V". It doesn't care if the device is a lamp, a fridge, or a computer — any device that matches the shape can plug in. The interface defines the shape; the class provides the wiring.

This is the foundation of: **dependency injection, SOLID principles (ISP, DIP), testability, plugin architectures, and polymorphism without inheritance**.

## 2. Deep Explanation

### Implicit vs Explicit Implementation

```csharp
public interface ILogger { void Log(string message); }
public interface IAuditor { void Log(string message); } // Same method name!

public class Service : ILogger, IAuditor
{
    // Implicit — available directly on the class
    public void Log(string message) => Console.WriteLine($"[LOG] {message}");

    // Explicit — only available via the interface reference
    void IAuditor.Log(string message) => Console.WriteLine($"[AUDIT] {message}");
}

var svc = new Service();
svc.Log("test");                    // Calls ILogger.Log (implicit)
((IAuditor)svc).Log("test");        // Calls IAuditor.Log (explicit)
```

**When to use explicit:** When two interfaces define the same member, or when you want to hide an interface method from the class's public API.

### Default Interface Methods (C# 8+)

Interfaces can now have method bodies. This allows adding new methods to an interface without breaking all existing implementations.

```csharp
public interface IPaymentGateway
{
    Task<bool> ChargeAsync(decimal amount);

    // Default method — existing implementations don't need to change
    Task<bool> RefundAsync(decimal amount) =>
        Task.FromResult(false); // Default: "refunds not supported"
}
```

### Key Interface Types in .NET

| Interface | Purpose | Why You Must Know It |
|-----------|---------|---------------------|
| `IEnumerable<T>` | Iteration | LINQ, foreach |
| `IDisposable` | Resource cleanup | using statement |
| `IComparable<T>` | Sorting | OrderBy, SortedSet |
| `IEquatable<T>` | Value equality | Dictionary keys, HashSet |
| `ICloneable` | Copying | **Avoid!** Returns `object`, not type-safe |
| `IAsyncDisposable` | Async cleanup | await using |

### Interface Segregation Principle (ISP)

```csharp
// ❌ Bad: Fat interface — forces implementations to handle everything
public interface IRepository<T>
{
    T GetById(int id);
    IList<T> GetAll();
    void Add(T entity);
    void Update(T entity);
    void Delete(int id);
    Task<T> GetByIdAsync(int id);
    Task BulkInsertAsync(IEnumerable<T> entities);
}

// ✅ Good: Segregated — implement only what you need
public interface IReadRepository<T> { T GetById(int id); IList<T> GetAll(); }
public interface IWriteRepository<T> { void Add(T entity); void Delete(int id); }
```

## 3. Code Examples

### Example 1 — Testability via Interfaces
```csharp
// Production
public interface IEmailSender { Task SendAsync(string to, string body); }

public class SmtpEmailSender : IEmailSender
{
    public async Task SendAsync(string to, string body) =>
        await _smtpClient.SendMailAsync(/* ... */);
}

// Test — swap implementation without changing business logic
public class FakeEmailSender : IEmailSender
{
    public List<string> SentEmails { get; } = new();
    public Task SendAsync(string to, string body)
    {
        SentEmails.Add($"{to}: {body}");
        return Task.CompletedTask;
    }
}
```

### Example 2 — IComparable and IEquatable
```csharp
public record Money(decimal Amount, string Currency)
    : IComparable<Money>, IEquatable<Money>
{
    public int CompareTo(Money? other)
    {
        if (other is null) return 1;
        if (Currency != other.Currency)
            throw new InvalidOperationException("Cannot compare different currencies");
        return Amount.CompareTo(other.Amount);
    }

    // IEquatable<T> is auto-generated by record, but shown for completeness
}

// Now works with sorting and collections
var prices = new SortedSet<Money> { new(100, "USD"), new(50, "USD"), new(75, "USD") };
// Sorted: 50, 75, 100
```

## 4. Interview Questions

1. **What is the difference between an interface and an abstract class?**
   *An interface defines a contract with no state (fields). A class can implement multiple interfaces but inherit only one abstract class. Abstract classes can have constructors, fields, and non-abstract methods. Since C# 8, interfaces can have default method implementations, but they still cannot have instance fields or constructors.*

2. **What is explicit interface implementation and when do you use it?**
   *Explicit implementation means the method is only accessible through the interface reference, not the class instance. Use it when two interfaces define the same method signature, or when you want to hide a method from the class's public surface area.*

3. **What are default interface methods (C# 8+) and why were they added?**
   *Default interface methods let you add new methods with implementations to an existing interface without breaking classes that already implement it. This solves the "interface versioning" problem — before C# 8, adding a method to a popular interface like `ILogger` would break every class implementing it.*

4. **Why should you avoid `ICloneable`?**
   *Its `Clone()` method returns `object`, requiring an unsafe cast. Worse, the interface doesn't specify whether it's a deep clone or shallow clone. It's better to define your own `ICopyable<T>` with a strongly-typed return, or use a copy constructor, or use `record` types with `with` expressions.*

5. **How do interfaces enable Dependency Injection?**
   *DI containers resolve services by interface type, not concrete type. Your controller depends on `IOrderService`, not `SqlOrderService`. At runtime, the DI container injects the correct implementation. In tests, you inject a mock. This inverts the dependency — high-level code doesn't know about low-level details.*

## 5. Edge Cases / Common Mistakes

```csharp
// MISTAKE 1: Fat interfaces that force empty implementations
public class ReadOnlyRepo : IRepository<User>
{
    public User GetById(int id) => _db.Find(id);
    public void Add(User u) => throw new NotSupportedException(); // ❌ Forced to implement!
    public void Delete(int id) => throw new NotSupportedException(); // ❌
}
// FIX: Segregate into IReadRepository<T> and IWriteRepository<T>

// MISTAKE 2: Casting to check interface — use 'is' pattern instead
if (obj.GetType().GetInterfaces().Contains(typeof(IDisposable))) { } // ❌ Verbose
if (obj is IDisposable d) { d.Dispose(); } // ✅ Clean

// MISTAKE 3: Default interface method not accessible via class
public interface IGreet { void Hello() => Console.WriteLine("Hi"); }
public class Service : IGreet { }
var s = new Service();
// s.Hello(); // ❌ Compile error! Default methods only accessible via interface
((IGreet)s).Hello(); // ✅ Works
```
